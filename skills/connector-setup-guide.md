# 连接器配置引导

## 原则
- 逐步询问**非敏感**字段（地址、项目 Key、表格 ID、字段映射）。**凭证不要在对话中输入**：配置里写成 `${secret:名称}`，引导用户到 设置 › 连接器 的密钥输入框填写（只写不读，只保存在本机配置文件）。
- 配置完成后执行“测试连接”；任何字段变化都要重新测试。stdio 命令首次添加或变化后，用户需要在界面上确认完整命令行。
- 连接器的查询结果是未经核实的外部数据，只能作为推测；Agent 只能调用标注为只读、且用户勾选开放的工具。写入外部系统不交给 Agent。

## 通用 MCP（streamable HTTP）
- 需要：MCP 服务地址（通常以 `/mcp` 结尾）、认证请求头（例如 `Authorization: Bearer ${secret:token}`）。
- 获取：对方 MCP 服务的文档或管理员；token 在对方系统的“个人访问令牌 / API Key”页面生成，只给只读权限。
- 常见错误：地址用了 http 且主机不在内网（只允许 https；内网主机可用 http）；地址会重定向（不跟随重定向，请填最终地址）；401（token 未填写或无权限）；服务返回的协议版本过旧（支持 2024-11-05 及之后）。

## 通用 MCP（本机命令，stdio）
- 需要：命令的**绝对路径**（例如 `/usr/local/bin/node`、`/opt/homebrew/bin/uvx`）、参数（每行一个）、需要的环境变量（凭证写 `${secret:名称}`）。
- 获取：MCP 服务的安装说明；用 `which <命令>` 找绝对路径。
- 常见错误：命令不是绝对路径或没有执行权限；依赖 PATH 中的其他程序（子进程只有命令所在目录和系统目录在 PATH 中，必要时把命令改成绝对路径）；依赖用户环境变量（子进程不继承本服务的环境，需要的变量要显式配置）；服务把日志写到 stdout（非 JSON 行会被忽略，但会拖慢响应）。

## 飞书 / Jira / 内部工单
- 当前版本通过对方提供的 **MCP 服务**接入（按上面两节配置）。专用的字段映射与状态双向同步在后续版本提供。
- Jira：需要站点地址、项目 Key、只读 API token；查询类工具（按关键字搜索工单）应标注为只读。
- 飞书：需要应用的 App ID 与 App Secret（写成 `${secret:...}`）、多维表格或文档的 ID；只开放读取类工具。
- 飞书文档（需求威胁建模读取需求、同步报告）：推荐使用飞书官方命令行工具 lark-cli（`npm i -g @larksuite/cli`，执行 `lark-cli auth login` 登录）与内置连接器包 `lark-cli`：在 设置 › 连接器包 安装示例 `lark-cli`，新建连接器（名称 `Feishu`、协议选连接器包、包选 `lark-cli`），确认命令后测试。读写能力由包里各操作声明，不需要另外配置。该包以你的 HOME 运行 lark-cli 以使用它自己的登录。也可以改用官方 MCP（lark-openapi-mcp，可从 Cursor 等已有配置导入），但内置指引按 lark-cli 编写，用 MCP 时需要在项目知识库中改写指引。
- 内部工单：连接器的工具（读写）默认都向 Agent 开放，Agent 按工具说明自行选择；不希望 Agent 使用的工具在连接器的工具列表里关闭。带有被审代码中疑似注入指令的调用会先暂停，等用户批准。

## 通用 HTTP（声明式模板）
- 当前版本尚未支持，请改用对方提供的 MCP 服务，或在内网部署一个 MCP 适配服务。
