# 写法规范（约 80% 遵循 ASD-STE100 原则）

目的：读者（产品、开发、安全、审计 Agent）读一遍就能理解，不会产生歧义。用中文写；不强制 STE 的英文受控词表。

## 必须遵守
1. **一句一事**：一句话只说一个事实、一条规则或一个动作。
2. **短句**：描述句尽量不超过 30 个字；超过时拆成两句或列表。
3. **主动语态，写明主语**：写“管理员审核退款申请”，不写“退款申请会被审核”。
4. **术语统一**：同一事物只用一个名称，第一次出现时定义（例如“订单所有者：下单的用户”）。不要在“用户 / 客户 / 买家”之间切换。
5. **不用模糊词**：不写“可能会在某些情况下”“一般”“适当”“等等”“相关”。写清楚条件：“当退款金额大于实付金额时”。
6. **先结论后原因**：先写“风险：……”，再写“原因：……”。
7. **数字与单位写全**：“每个用户每天最多 3 次”，不写“次数有限制”。
8. **来源标注**：在句末用括号标来源，例如“（S1）”“（S2、S3）”。

## 建议遵守
- 用列表代替长段落；列表项以名词或动词开头，格式一致。
- 否定句写明确：“未登录用户不能查看订单”，不写“订单查看有一定限制”。
- 一个列表项只写一个条件。

## 示例
- 不好：退款功能可能存在一定的安全风险，需要适当加强校验。
- 好：风险：用户可以为不属于自己的订单申请退款。原因：需求没有要求校验订单所有者（S1）。
