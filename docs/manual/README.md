# 獬豸 xiezhi-audit 使用手册

獬豸（Xiezhi）是在本机运行的代码安全审计 Agent。它只做**静态审计**：不构建、不运行、不测试被审代码。它结合大模型、结构索引（tree-sitter）、内置规则与知识库来发现漏洞，并给出证据链、复核结论和报告。

本手册介绍 Web 工作台和命令行的全部功能模块。每个模块都配有真实运行截图。

> 截图环境：本地模型网关 magpie（`http://127.0.0.1:3425/v1`，OpenAI Chat Completions 协议），默认模型 `anthropic/claude-haiku-5-5`，备用模型 `antigravity/gemini-3.8-flash`。示例项目是开源的现货交易所演示仓库 CEX-Demo（TypeScript monorepo：10 个后端服务、交易端与运营后台，约 800 个文件），用的是它的安全训练靶场分支 `hunter/vuls`，仓库放在演示目录 `/Users/Shared/xiezhi-demo/CEX-Demo`。截图中的数据都来自真实运行。

## 典型使用流程

```text
安装并运行 xiezhi doctor
  → 启动 xiezhi serve，用一次性链接登录
  → 设置 › 模型：添加模型服务，设置默认 / 备用模型
  → 新建项目，添加仓库（本地目录 / Git / 压缩包），可选 AI 识别仓库角色
  → 新建审计（可先看计划），回答 Agent 提问，跟踪执行
  → 在结果和漏洞清单中复核：确认、误报、调整严重度
  → 修复后发起复验，或做增量审计
  → 导出报告（Markdown / HTML / JSON / SARIF），或推送到工单系统
```

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 项目 | 对应一个业务系统，可以包含多个仓库。漏洞、威胁模型、企业事实、项目知识都挂在项目下。 |
| 仓库 | 本地目录、Git 地址或压缩包。每个仓库可以设为“可审计”或“只作证据”，并有 AI 识别的角色（网关、业务服务等）。 |
| 审计 | 一次审计任务。场景有全量审计、增量审计、风险排查和漏洞复验；模式有单仓库审计和多仓库合并审计。 |
| 发现 / 漏洞 | 审计中的结论叫“发现”（F-编号）。归并后进入项目的漏洞清单（V-编号），跨审计跟踪状态：新增、仍存在、已修复（经验证）、回归。 |
| 企业事实 | 代码里看不到的环境前提，例如网关鉴权、部署拓扑、网络边界。你回答 Agent 提问时，答案可以存为事实，后续审计直接使用。 |
| 知识（skill） | Markdown 写成的审计方法、漏洞案例、报告规范等。Agent 先看到索引，需要时再读取正文。 |
| 预算 | 每次审计的 token 和时长上限，启动时冻结。用完后审计暂停，等你追加预算。 |

## 安全边界

- 被审仓库、检索到的文档和连接器返回的内容都按不可信数据处理。被审仓库里的 `AGENTS.md`、`SKILL.md` 等控制文件不会对 Agent 可见。
- 连接器写操作的参数或会话中出现疑似注入指令时，调用会暂停，等用户批准。
- 模型密钥与 Git 凭证只保存在本机数据目录（默认 `~/.xiezhi-code-audit`）。日志、轨迹和导出内容中的密钥会脱敏。
- 本地服务只监听 `127.0.0.1`，浏览器要用一次性链接登录（见 [第 1 章](01-install-and-setup.md#登录-web-工作台)）。
